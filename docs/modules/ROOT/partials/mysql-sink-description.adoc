== MySQL Sink Kamelet Description

=== Database Connection

This Kamelet connects to MySQL databases using the MySQL Connector/J JDBC driver, which is not a dependency of the Kamelet: add `mvn:com.mysql:mysql-connector-j` to the integration (Camel JBang adds it by itself). MySQL is one of the world's most popular open-source relational database management systems.

=== Data Processing

The Kamelet expects JSON input data which is automatically unmarshalled before executing the SQL query. This allows for seamless integration with JSON-based data sources.

=== Parameterized Queries

SQL queries use named parameters (e.g., `:#username`, `:#city`) that map to fields in the incoming JSON data. This approach provides protection against SQL injection attacks while maintaining query flexibility.

=== Connection Management

Uses Apache Commons DBCP2 for efficient database connection pooling. This provides optimal resource utilization and connection lifecycle management.

=== Authentication and Security

Requires username and password authentication for database access.

=== Connecting with TLS

Set `connectionProperties` to pass settings to the MySQL JDBC driver (Connector/J), as `name=value` pairs separated by
`;`. Without it, the driver uses TLS only when the server offers it, and does not check the certificate of the server.
Set `sslMode=REQUIRED` to always use TLS.

[source,yaml,subs='+attributes,macros']
----
connectionProperties: "sslMode=REQUIRED"
----

=== Writing Several Rows from One Message

With `batch` set to true, the body can be a JSON array of objects. `query` runs once for each object, and all of them
are written in one database transaction: when one of them fails, none is written. The `CamelSqlUpdateCount` header
then holds the number of rows written for the whole message. A single JSON object still works.

[source,yaml,subs='+attributes,macros']
----
- route:
    from:
      uri: "timer:accounts?repeatCount=1"
      steps:
        - setBody:
            constant: '[{"username":"oscerd","city":"Rome"},{"username":"ann","city":"Oslo"}]'
        - to:
            uri: "kamelet:mysql-sink"
            parameters:
              serverName: "db.example.com"
              username: "dbuser"
              password: "dbpass"
              databaseName: "shop"
              query: "INSERT INTO accounts (username,city) VALUES (:#username,:#city)"
              batch: true
----

=== Connection Pool

The Kamelet keeps a pool of connections to the database:

* `maxTotal`: the most connections it opens at the same time, 8 when not set.
* `maxIdle`: the most unused connections it keeps open, 8 when not set.
* `maxWaitMillis`: how long a message waits for a free connection when `maxTotal` are in use, in milliseconds, before
  it fails. When not set, it waits as long as it takes.

[source,yaml,subs='+attributes,macros']
----
maxTotal: 4
maxIdle: 2
maxWaitMillis: 5000
----
