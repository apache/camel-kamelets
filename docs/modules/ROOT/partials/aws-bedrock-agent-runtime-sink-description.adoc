== AWS Bedrock Agent Runtime Sink Kamelet Description

=== Authentication methods

In this Kamelet you can avoid using explicit static credentials by specifying the `useDefaultCredentialsProvider` option and set it to `true`.

The order of evaluation for Default Credentials Provider is the following:

 - Java system properties - `aws.accessKeyId` and `aws.secretKey`.
 - Environment variables - `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`.
 - Web Identity Token from AWS STS.
 - The shared credentials and config files.
 - Amazon ECS container credentials - loaded from the Amazon ECS if the environment variable `AWS_CONTAINER_CREDENTIALS_RELATIVE_URI` is set.
 - Amazon EC2 Instance profile credentials. 
 
You can also use the Profile Credentials Provider, by setting the `useProfileCredentialsProvider` option to `true` and `profileCredentialsName` to the profile name.

Only one of access key/secret key or default credentials provider could be used

For more information, see the https://docs.aws.amazon.com/sdk-for-java/latest/developer-guide/credentials.html[AWS credentials documentation]

=== Through an HTTP Proxy

Where AWS can be reached only through an HTTP proxy, as in many company networks, set `proxyHost` and `proxyPort` to the proxy. `proxyProtocol` is how the Kamelet talks to the proxy itself, not to AWS: it is `HTTPS` when it is not set, so set it to `HTTP` for a proxy that takes plain HTTP, such as Squid. The calls to AWS stay encrypted, as the proxy only passes them on. The Kamelet has no option for a proxy user or password.

The step that sends to the Kamelet, in a route:

[source,yaml,subs='+attributes,macros']
----
- to:
    uri: "kamelet:aws-bedrock-agent-runtime-sink"
    parameters:
      modelId: "anthropic.claude-v2"
      knowledgeBaseId: "AB12CD34EF"
      region: "eu-west-1"
      useDefaultCredentialsProvider: true
      proxyHost: "proxy.example.com"
      proxyPort: 3128
      proxyProtocol: "HTTP"
----

=== Operations

`operation` chooses what the Kamelet does with the question in the body:

[width="100%",cols="1,3,2",options="header"]
|===
| `operation` | What it does | Options it needs
| `retrieveAndGenerate` (default)
| Finds the passages that match the question in the knowledge base, and has the model write the answer from them. The
  body afterwards is the answer, as text.
| `modelId`, `knowledgeBaseId`
| `retrieve`
| Only finds the passages, without an answer. The body afterwards is a List of the passages, each with its text
  (`content.text`), its `score` and the `location` of its document. `numberOfResults` limits how many, and `searchType`
  chooses between a `SEMANTIC` and a `HYBRID` search.
| `knowledgeBaseId`
| `invokeAgent`
| Sends the question to a Bedrock agent, which answers it with its own instructions, knowledge bases and actions. The
  body afterwards is the answer, as text.
| `agentId`, `agentAliasId`
|===

The passages from `retrieve` are objects of the AWS SDK for Java, not JSON: turned into JSON as they are, each is an
empty object. Take the parts you need in the next step. For example, to keep the text of the first passage:

[source,yaml,subs='+attributes,macros']
----
- to:
    uri: "kamelet:aws-bedrock-agent-runtime-sink"
    parameters:
      operation: "retrieve"
      knowledgeBaseId: "AB12CD34EF"
      numberOfResults: 3
      searchType: "HYBRID"
      region: "us-east-1"
      useDefaultCredentialsProvider: true
- setBody:
    simple: "$\{body[0].content.text}"
----

To ask an agent, and continue the conversation with the session ID of the answer:

[source,yaml,subs='+attributes,macros']
----
- to:
    uri: "kamelet:aws-bedrock-agent-runtime-sink"
    parameters:
      operation: "invokeAgent"
      agentId: "KX7Q2M9WZB"
      agentAliasId: "TSTALIASID"
      region: "us-east-1"
      useDefaultCredentialsProvider: true
----

Without the `CamelAwsBedrockAgentRuntimeSessionId` header, each message starts a new session, and the header holds
its ID afterwards. Send that ID in the header with the next question to continue the same conversation.
