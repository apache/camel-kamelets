== MongoDB Sink Kamelet Description

=== NoSQL Database Integration

This Kamelet integrates with MongoDB, a popular NoSQL document database. MongoDB stores data in flexible, JSON-like documents, making it ideal for applications requiring dynamic schemas.

=== SSL/TLS Security

The Kamelet supports SSL/TLS encryption for secure connections to MongoDB. SSL is enabled by default, and certificate validation can be configured based on security requirements.

=== Authentication

Optional username and password authentication is supported for secured MongoDB instances, for a user defined in the `admin` database. The Kamelet uses SSL-aware MongoDB client connections for secure data transmission. For MongoDB Atlas, or a user defined in another database, use a connection string instead, as shown below.

=== Write Operations

The `operation` option says what the Kamelet does with each message:

[width="100%",cols="1,2,2",options="header"]
|===
| `operation` | Body | What happens
| `insert` (default)
| One document as a JSON object, such as `{"_id":"o-1","item":"book","qty":2}`
| The document is added. A document whose `_id` is already in the collection fails.
| `save`
| One document as a JSON object, such as `{"_id":"o-1","item":"book","qty":5}`
| The stored document with the same `_id` is replaced as a whole: fields that are not in the body are removed. When
  there is none, or the body has no `_id`, the document is added.
| `update`
| A JSON array of the filter and the changes, such as `[{"sku":"A1"},{"$set":{"qty":3}}]`
| The first document that matches the filter is changed. The changes must use update operators, such as `$set`,
  `$inc` or `$unset`. When no document matches, nothing is written, unless `upsert` is true.
|===

An ObjectId is written in the body as `{"$oid":"6afd00000000000000000001"}`. With `insert` and `save`, the
`CamelMongoOid` header holds the `_id` of the document. With `update`, the `CamelMongoDbRecordsMatched` and
`CamelMongoDbRecordsAffected` headers say how many documents matched and how many were changed. The `db-upsert` and
`ce-dbupsert` headers are not used.

=== Example with Update and Upsert

With `upsert` true, the first message for a product inserts `{"sku":"A1","qty":2}`, and each later one updates it:

[source,yaml,subs='+attributes,macros']
----
- route:
    from:
      uri: "kamelet:kafka-source"
      parameters:
        topic: "stock"
        bootstrapServers: "kafka.example.com:9092"
        saslAuthType: "NONE"
      steps:
        # each record is a JSON array such as [{"sku":"A1"},{"$set":{"qty":2}}]
        - to:
            uri: "kamelet:mongodb-sink"
            parameters:
              hosts: "mongo1.example.com:27017"
              username: "mongouser"
              password: "mongopass"
              database: "shop"
              collection: "stock"
              operation: "update"
              upsert: true
----

To keep a copy of records by their ID instead, set `operation` to `save` and send each record as a document with its
`_id`.

=== Write Concerns

Configurable write concern levels ensure data durability and consistency based on application requirements. Options include acknowledged, journaled, majority, and various numbered write concerns.

=== Collection Management

The Kamelet can optionally create collections during initialization if they don't exist (`createCollection`). When `createCollection` is false, the default, the Kamelet fails to start if the collection does not exist.

=== Connecting with a connection string

Set either `hosts` or `connectionString`. Use `connectionString` to connect to MongoDB Atlas with its
`mongodb+srv://` string, to log in as a user defined in a database other than `admin` (with `authSource`), or to give
other settings of the MongoDB connection string, such as `replicaSet` or `tls`. When it is set, `hosts`, `username`,
`password`, `ssl` and `sslValidationEnabled` are not used, and TLS is used as the string says: always with
`mongodb+srv://`, and with `mongodb://` only when it has `tls=true`.

Write `@`, `/`, `:` and `%` in the user name or the password as `%40`, `%2F`, `%3A` and `%25`. The connection string
holds the password, so keep it in a secret, like the `password` option.

With MongoDB Atlas, copy the string from the Connect dialog of the cluster:

[source,yaml,subs='+attributes,macros']
----
- route:
    from:
      uri: "kamelet:kafka-source"
      parameters:
        topic: "orders"
        bootstrapServers: "kafka.example.com:9092"
        saslAuthType: "NONE"
      steps:
        - to:
            uri: "kamelet:mongodb-sink"
            parameters:
              connectionString: "mongodb+srv://myuser:mypassword@cluster0.abcde.mongodb.net/?retryWrites=true&w=majority"
              database: "shop"
              collection: "orders"
----

For a user defined in the `shop` database, on a MongoDB without TLS:

[source,yaml,subs='+attributes,macros']
----
connectionString: "mongodb://shopuser:shoppass@mongo1.example.com:27017,mongo2.example.com:27017/?authSource=shop&replicaSet=rs0"
----
