== AWS S3 Streaming Upload Sink Kamelet Description

=== Authentication methods

In this Kamelet you can avoid using explicit static credentials by specifying the `useDefaultCredentialsProvider` option and set it to `true`.

The order of evaluation for Default Credentials Provider is the following:

 - Java system properties - `aws.accessKeyId` and `aws.secretKey`.
 - Environment variables - `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`.
 - Web Identity Token from AWS STS.
 - The shared credentials and config files.
 - Amazon ECS container credentials - loaded from the Amazon ECS if the environment variable `AWS_CONTAINER_CREDENTIALS_RELATIVE_URI` is set.
 - Amazon EC2 Instance profile credentials. 
 
You can also use the Profile Credentials Provider, by setting the `useProfileCredentialsProvider` option to `true` and `profileCredentialsName` to the profile name.

Only one of access key/secret key or default credentials provider could be used

For more information, see the https://docs.aws.amazon.com/sdk-for-java/latest/developer-guide/credentials.html[AWS credentials documentation]

=== File names

The name of the files comes from the `keyName` option, not from headers.

With the default `namingStrategy` of `progressive` and a `keyName` of `logs/app.log`, the first file is `logs/app.log` and the next ones are `logs/app-1.log`, `logs/app-2.log` and so on. With `random` or `timestamp`, a random ID or the time in milliseconds is added to the name instead of a number.

=== Example with Encryption by a KMS Key and a Storage Class

A bucket policy can require every file to be encrypted with a given key of AWS KMS (SSE-KMS); an upload without it is
refused with `AccessDenied`. Set **useAwsKMS** and **awsKMSKeyId** to encrypt the files with that key, and
**storageClass** to store them in another class than `STANDARD`:

[source,yaml,subs='+attributes,macros']
----
- route:
    from:
      uri: "kamelet:kafka-source"
      parameters:
        topic: "invoices"
        bootstrapServers: "kafka.example.com:9092"
        saslAuthType: "NONE"
      steps:
        - setBody:
            simple: "$\{body}\n"
        - to:
            uri: "kamelet:aws-s3-streaming-upload-sink"
            parameters:
              bucketNameOrArn: "my-bucket"
              region: "eu-west-1"
              useDefaultCredentialsProvider: true
              keyName: "invoices/invoices.jsonl"
              useAwsKMS: true
              awsKMSKeyId: "arn:aws:kms:eu-west-1:111122223333:key/1234abcd-12ab-34cd-56ef-1234567890ab"
              storageClass: "STANDARD_IA"
----

The credentials need the permission to use the key (`kms:GenerateDataKey`), and whoever reads the files the permission
to decrypt with it (`kms:Decrypt`). Without **awsKMSKeyId**, the files are encrypted with the key that AWS manages for S3 (`aws/s3`). To ask for the encryption with keys that S3 manages
(SSE-S3) instead, as some bucket policies require, set **useSSES3** to `true`. The storage class can be any class of
S3, such as `STANDARD_IA`, `INTELLIGENT_TIERING` or `GLACIER_IR`; a file in `GLACIER` or `DEEP_ARCHIVE` must be restored
before it can be read. A `CamelAwsS3StorageClass` header on the message takes precedence over **storageClass**.

=== Through an HTTP Proxy

Where AWS can be reached only through an HTTP proxy, as in many company networks, set `proxyHost` and `proxyPort` to the proxy. `proxyProtocol` is how the Kamelet talks to the proxy itself, not to AWS: it is `HTTPS` when it is not set, so set it to `HTTP` for a proxy that takes plain HTTP, such as Squid. The calls to AWS stay encrypted, as the proxy only passes them on. The Kamelet has no option for a proxy user or password.

The step that sends to the Kamelet, in a route:

[source,yaml,subs='+attributes,macros']
----
- to:
    uri: "kamelet:aws-s3-streaming-upload-sink"
    parameters:
      bucketNameOrArn: "my-bucket"
      region: "eu-west-1"
      keyName: "logs/app.log"
      useDefaultCredentialsProvider: true
      proxyHost: "proxy.example.com"
      proxyPort: 3128
      proxyProtocol: "HTTP"
----
