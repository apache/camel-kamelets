== Kafka Sink Kamelet Description

=== Authentication

The `saslAuthType` option chooses how the Kamelet logs in to Kafka. The options that each type needs are listed below;
leave the others empty.

[width="100%",cols="1,3",options="header"]
|===
| `saslAuthType` | Options to set
| `NONE` | None. No login and no TLS, as a local Kafka expects.
| `PLAIN`, `SCRAM_SHA_256`, `SCRAM_SHA_512` | `saslUsername` and `saslPassword`.
| `SSL` | `sslTruststoreLocation` and `sslTruststorePassword`; for mutual TLS also `sslKeystoreLocation`, `sslKeystorePassword` and `sslKeyPassword`.
| `OAUTH` | `oauthClientId`, `oauthClientSecret` and `oauthTokenEndpointUri`; `oauthScope` when the provider asks for one.
| `AWS_MSK_IAM` | None in the Kamelet: the AWS credentials are taken from the environment the integration runs in.
| `KERBEROS` | None in the Kamelet: Kerberos is configured in the environment the integration runs in.
|===

=== Schema registry

To write the records with a schema kept in a schema registry, set `schemaRegistryVendor`, `schemaRegistryUrl` and
`schemaFormat` (the default is `avro`). With `json`, the body must be JSON text (or a Map); the Kamelet turns it into
an object, and the record is written with a JSON Schema made from it, which accepts any JSON object. With `avro`, a
text body is written as an Avro string; an Avro record needs a step that creates it in code. The sink registers the
schema it makes, and does not check the message against a schema that is already registered for the topic.

[width="100%",cols="1,1,3",options="header"]
|===
| `schemaRegistryVendor` | `schemaFormat` | Registry
| `confluent` | `avro`, `json` | Confluent Schema Registry, and the registries with the same API, such as the one of Redpanda and Karapace. `schemaRegistryUrl` is the URL of the registry, such as `http://localhost:8081`.
| `apicurio` | `avro` | Apicurio Registry 3.x. `schemaRegistryUrl` is the URL of the registry API, such as `http://localhost:8080/apis/registry/v3`.
|===

The serde jars of the vendor are not part of the Kamelet. Camel JBang downloads them by itself; the Confluent jars are
in the Confluent Maven repository, not in Maven Central, so run with `--repos=confluent`. In a Maven project, add the
jar of the vendor and format, such as `io.confluent:kafka-avro-serializer`, and for Confluent the repository
`https://packages.confluent.io/maven/`. A schema registry that requires a login is not supported yet.

[source,yaml,subs='+attributes,macros']
----
- route:
    from:
      uri: "kamelet:timer-source"
      parameters:
        period: 10000
        message: '{"id": 42, "item": "book"}'
        contentType: application/json
      steps:
        - to:
            uri: "kamelet:kafka-sink"
            parameters:
              bootstrapServers: "localhost:9092"
              topic: orders
              saslAuthType: NONE
              schemaRegistryVendor: confluent
              schemaRegistryUrl: "http://localhost:8081"
              schemaFormat: json
----

=== Usage example

The route below sends a JSON order every ten seconds to the `orders` topic, with the order number as the record key.

[source,yaml,subs='+attributes,macros']
----
- route:
    from:
      uri: "kamelet:timer-source"
      parameters:
        period: 10000
        message: '{"id": 42, "item": "book"}'
        contentType: application/json
      steps:
        - setHeader:
            name: key
            constant: "42"
        - to:
            uri: "kamelet:kafka-sink"
            parameters:
              bootstrapServers: "localhost:9092"
              topic: orders
              saslAuthType: NONE
----
