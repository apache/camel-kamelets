== SFTP Sink Kamelet Description

=== Secure File Transfer Protocol

This Kamelet provides secure file transfer capabilities using SFTP (SSH File Transfer Protocol). SFTP enables encrypted file transfers over SSH connections with comprehensive file management features.

=== SSH-Based Security

Built on top of SSH protocol, SFTP provides strong authentication and encryption for all file transfer operations, ensuring data confidentiality and integrity.

=== File Operations

The sink uploads each message as a file into `directoryName`, and creates missing directories when `autoCreate` is true. What happens when the file already exists is set by `fileExist` (`Override`, `Append`, `Fail` or `Ignore`). To keep a reader from picking up a half-written file, `tempPrefix` uploads each file under a temporary name and renames it once it is complete, and `doneFileName` writes an empty done file next to it; see the example below. To read files from an SFTP server, use the SFTP Source Kamelet.

=== Authentication Methods

Supports these authentication mechanisms:

- Username and password authentication
- Private key authentication (`privateKeyFile` or `privateKeyUri`, with `privateKeyPassphrase` for a protected key)
- Host key verification against a known_hosts file (`knownHostsUri`, or `~/.ssh/known_hosts` of the user that runs the integration); with the default `strictHostKeyChecking` of `yes`, a server that is not in it is refused

=== Cross-Platform Compatibility

Works seamlessly across different operating systems and platforms, providing consistent secure file transfer capabilities in heterogeneous environments.

=== Optional Headers

In the header, you can optionally set the `file` / `ce-file` property to specify the name of the file to upload.

If you do not set the property in the header, the Kamelet uses a default naming convention.

The value is reduced to a single file name before use: any directory component is
dropped, so `reports/2026/data.csv` is stored as `data.csv`. The file is always
written inside the configured directory.

=== Example with a Temporary Name and a Done File

By default a file is uploaded under its real name from the start, so a reader that polls the directory can pick it up
half-written. Set **tempPrefix**, **doneFileName**, or both, to prevent that:

[source,yaml,subs='+attributes,macros']
----
- route:
    from:
      uri: "timer:tick"
      parameters:
        period: 60000
      steps:
        - setBody:
            constant: "order-1,42"
        - setHeader:
            name: file
            constant: "orders.csv"
        - to:
            uri: "kamelet:sftp-sink"
            parameters:
              connectionHost: "sftp.example.com"
              username: "sftpuser"
              password: "sftppass"
              directoryName: "/incoming"
              tempPrefix: ".tmp-"
              doneFileName: "${file:name}.done"
----

Each file is uploaded as `.tmp-orders.csv` and renamed to `orders.csv` once the upload is complete, and then an empty
`orders.csv.done` is written next to it. The SFTP Source Kamelet, like other readers built with Camel, skips the names that start
with a dot, so it never reads a half-written file; another reader can wait for the `.done` file. In **doneFileName**,
`${file:name}` stands for the name of the file and `${file:name.noext}` for the name without its extension; no other
`${...}` is allowed. The user needs the right to rename files on the server. **tempPrefix** cannot be combined with
**fileExist** set to `Append`, and with `Override` a file of the same name is deleted when the upload starts.

=== Example with File Permissions

[source,yaml,subs='+attributes,macros']
----
- route:
    from:
      uri: "kamelet:timer-source"
      parameters:
        message: "Hello"
      steps:
        - to:
            uri: "kamelet:sftp-sink"
            parameters:
              connectionHost: "sftp.example.com"
              username: "sftpuser"
              password: "sftppass"
              directoryName: "/upload"
              chmod: "640"
              serverAliveInterval: 30000
----

Each file gets the permissions `640` once it is written, read and write for its owner and read for the group, also
when it replaced a file with other permissions. Without **File Permissions**, a new file gets the permissions the
server gives it, usually `644`. **Server Alive Interval** checks every 30 seconds without data that the server still
answers, and closes the connection when it does not, so that the next message makes a new one.
