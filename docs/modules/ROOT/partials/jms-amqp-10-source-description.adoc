== JMS AMQP 1.0 Source Kamelet Description

=== Login and TLS

The Kamelet has no separate options for the login or TLS: they go in `remoteURI`, as settings of the Apache Qpid JMS
client after `?`.

- A login: `amqp://broker.example.com:5672?jms.username=app&jms.password=secret`
- TLS: the `amqps://` scheme, with `transport.trustStoreLocation` and `transport.trustStorePassword` when the broker
  certificate is not trusted by the Java runtime.

=== Output format

The body is text for a JMS text message, bytes for a bytes message, and a Map for a map message. The JMS properties of
the message become headers.

=== Configuration

The Kamelet requires connection parameters for the AMQP 1.0 broker:

- `remoteURI`: the address of the broker, with the login when the broker needs one
- `destinationName`: the name of the queue or topic
- `destinationType`: `queue` (the default) or `topic`
- `subscriptionDurable`, `subscriptionShared`, `subscriptionName` and `clientId`: a durable or shared subscription to
  a topic (see below)
- `selector`: receive only the messages that match a condition on their properties and headers

=== Usage example

[source,yaml,subs='+attributes,macros']
----
- route:
    from:
      uri: "kamelet:jms-amqp-10-source"
      parameters:
        remoteURI: "amqp://broker.example.com:5672?jms.username=app&jms.password=secret"
        destinationName: "my-queue"
      steps:
        - to:
            uri: "kamelet:log-sink"
----

=== Durable topic subscription

From a topic, the source receives by default only the messages published while it is connected. With
`subscriptionDurable` set to `true`, the broker keeps the messages published while the source is stopped, and delivers
them when it starts again. The broker keeps the subscription under the client ID and the subscription name, so use the
same `clientId` and `subscriptionName` each time the source starts.

[source,yaml,subs='+attributes,macros']
----
- route:
    from:
      uri: "kamelet:jms-amqp-10-source"
      parameters:
        remoteURI: "amqp://broker.example.com:5672?jms.username=app&jms.password=secret"
        destinationName: "events"
        destinationType: "topic"
        subscriptionDurable: true
        subscriptionName: "audit"
        clientId: "audit-service"
      steps:
        - to:
            uri: "kamelet:log-sink"
----

The JMS rules to know:

- A durable subscription that is not shared needs a `clientId`. Without one, the source starts but receives nothing,
  and logs that a client ID must be set.
- Only one connection may use a client ID at a time: two running copies of the source need different client IDs.
- To run several copies of the source on one durable subscription, set `subscriptionShared` to `true` as well, and
  leave `clientId` empty: the copies share the messages of the topic by `subscriptionName`, each message going to one
  of them. Shared subscriptions are part of JMS 2.0.
- The durable subscription stays on the broker, and keeps collecting messages, until it is removed in the broker.

=== Message selector

With `selector`, the source receives only the messages that match it, a condition on the JMS properties and headers of
the message, such as `priority > 5`. From a queue, the other messages stay on the queue.
