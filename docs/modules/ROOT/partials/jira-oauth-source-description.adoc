== Jira oauth Source Kamelet Description

=== Authentication methods

This Kamelet uses OAuth 1.0a to connect to JIRA, through an application link that a Jira administrator sets up for
incoming authentication. You need to provide:

- `consumerKey`: the consumer key of the application link
- `privateKey`: the RSA private key whose public key is set in the application link, in PKCS8 format, Base64 encoded on
  one line, without the `BEGIN` and `END` lines
- `verificationCode`: the verification code (verifier) that Jira shows when the user allows the access
- `accessToken`: the access token that Jira gives at the end of the authorization
- `jiraUrl`: the address of your Jira

To log in with a user and an API token, or with a personal access token, use `jira-source` instead.

=== Output format

The Kamelet sends each new issue that matches the JQL query as one message, with the issue as JSON text. Only the
issues created after the Kamelet starts are sent. It checks for new issues every 6 seconds.

=== Configuration

The Kamelet requires the following parameters:

- `jiraUrl`: The address of your Jira
- `accessToken`: The access token generated by the JIRA server
- `verificationCode`: The verification code generated by the JIRA server
- `consumerKey`: The consumer key of the application link
- `privateKey`: The private key whose public key is set in the application link
- `jql`: The JQL query that selects the issues, without `ORDER BY`

=== Usage example

[source,yaml,subs='+attributes,macros']
----
- route:
    from:
      uri: "kamelet:jira-oauth-source"
      parameters:
        jiraUrl: "https://jira.mycompany.com"
        accessToken: "{{jira.accessToken}}"
        verificationCode: "{{jira.verificationCode}}"
        consumerKey: "{{jira.consumerKey}}"
        privateKey: "{{jira.privateKey}}"
        jql: "project = SHOP"
      steps:
        - to:
            uri: "kamelet:log-sink"
----
