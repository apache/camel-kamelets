== AWS SQS Batch Sink Kamelet Description

=== Authentication methods

In this Kamelet you can avoid using explicit static credentials by specifying the `useDefaultCredentialsProvider` option and set it to `true`.

The order of evaluation for Default Credentials Provider is the following:

 - Java system properties - `aws.accessKeyId` and `aws.secretKey`.
 - Environment variables - `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`.
 - Web Identity Token from AWS STS.
 - The shared credentials and config files.
 - Amazon ECS container credentials - loaded from the Amazon ECS if the environment variable `AWS_CONTAINER_CREDENTIALS_RELATIVE_URI` is set.
 - Amazon EC2 Instance profile credentials. 
 
You can also use the Profile Credentials Provider, by setting the `useProfileCredentialsProvider` option to `true` and `profileCredentialsName` to the profile name.

Only one of access key/secret key or default credentials provider could be used

For more information, see the https://docs.aws.amazon.com/sdk-for-java/latest/developer-guide/credentials.html[AWS credentials documentation]

=== Delaying the Messages

`delaySeconds` keeps each message hidden for that many seconds after it is sent, up to 900 (15 minutes), before a reader can receive it. Use it to process a message later, such as a retry in a minute.

=== Without Permission to List the Queues

By default the Kamelet finds the address of the queue by listing the queues, which needs the `sqs:ListQueues` permission. It does not list the queues when it is given the address:

- **Queue URL** (`queueURL`): the full address of the queue, as the SQS console shows it.
- **Queue Owner AWS Account ID** (`queueOwnerAWSAccountId`): the 12-digit ID of the account that owns the queue. The address is then built from the account, the region and the queue name. Use it for a queue of another AWS account too.
- An ARN in **Queue Name** (`queueNameOrArn`), which holds the account.

=== Too Many Headers

An SQS message takes at most 10 message attributes. The headers of the message are sent with each part. When a message has more than 10 headers to send, the first 10 are sent with each part, and `messageHeaderExceededLimit` sets what happens to the others: `WARN` (the default) logs a warning for each one, `WARN_ONCE` logs one warning for each part, `IGNORE` logs nothing, and `FAIL` fails the message, which is then not sent.

=== Encrypting the Queue

`serverSideEncryptionEnabled` and `kmsMasterKeyId` set the queue to encrypt its messages with a key of AWS KMS (SSE-KMS). They change the queue itself, not only the messages of this Kamelet: when the integration starts, an existing queue is updated, which needs the `sqs:SetQueueAttributes` permission, and a queue that `autoCreateQueue` creates is created with the key. `serverSideEncryptionEnabled` without `kmsMasterKeyId` has no effect.

For example, to send to a queue without listing the queues, with each part delayed by one minute:

[source,yaml]
----
- to:
    uri: "kamelet:aws-sqs-batch-sink"
    parameters:
      queueNameOrArn: "orders"
      region: "eu-west-1"
      queueURL: "https://sqs.eu-west-1.amazonaws.com/123456789012/orders"
      batchSeparator: ","
      delaySeconds: 60
----

=== Through an HTTP Proxy

Where AWS can be reached only through an HTTP proxy, as in many company networks, set `proxyHost` and `proxyPort` to the proxy. `proxyProtocol` is how the Kamelet talks to the proxy itself, not to AWS: it is `HTTPS` when it is not set, so set it to `HTTP` for a proxy that takes plain HTTP, such as Squid. The calls to AWS stay encrypted, as the proxy only passes them on. The Kamelet has no option for a proxy user or password.

The step that sends to the Kamelet, in a route:

[source,yaml,subs='+attributes,macros']
----
- to:
    uri: "kamelet:aws-sqs-batch-sink"
    parameters:
      queueNameOrArn: "orders"
      region: "eu-west-1"
      batchSeparator: ","
      useDefaultCredentialsProvider: true
      proxyHost: "proxy.example.com"
      proxyPort: 3128
      proxyProtocol: "HTTP"
----
