== MariaDB Sink Kamelet Description

=== Database Connection

This Kamelet connects to MariaDB databases using JDBC. MariaDB is a popular open-source relational database management system that is a compatible drop-in replacement for MySQL.

=== Data Processing

The Kamelet expects JSON input data which is unmarshalled before executing the SQL query. The input data fields can be referenced in the SQL query using named parameters.

=== Query Configuration

The SQL query should use named parameters (e.g., `:#username`, `:#city`) that correspond to fields in the incoming JSON data. This allows for safe parameterized queries that prevent SQL injection attacks.

=== Connection Pooling

The Kamelet uses Apache Commons DBCP2 for connection pooling, providing efficient database connection management and resource optimization.

=== Authentication

Requires username and password authentication for secure database access. These credentials should be properly managed and secured.

=== Connecting with TLS

Set `connectionProperties` to pass settings to the MariaDB JDBC driver (MariaDB Connector/J), as `name=value` pairs
separated by `;`. Without it, the default of the driver applies, and it depends on its version: Connector/J 3 connects
without TLS, Connector/J 4 with TLS. Set `sslMode=trust` to always use TLS, without checking the certificate of the
server.

[source,yaml,subs='+attributes,macros']
----
connectionProperties: "sslMode=trust"
----

=== Writing Several Rows from One Message

With `batch` set to true, the body can be a JSON array of objects. `query` runs once for each object, and all of them
are written in one database transaction: when one of them fails, none is written. The `CamelSqlUpdateCount` header
then holds the number of rows written for the whole message. A single JSON object still works.

[source,yaml,subs='+attributes,macros']
----
- route:
    from:
      uri: "timer:accounts?repeatCount=1"
      steps:
        - setBody:
            constant: '[{"username":"oscerd","city":"Rome"},{"username":"ann","city":"Oslo"}]'
        - to:
            uri: "kamelet:mariadb-sink"
            parameters:
              serverName: "db.example.com"
              username: "dbuser"
              password: "dbpass"
              databaseName: "shop"
              query: "INSERT INTO accounts (username,city) VALUES (:#username,:#city)"
              batch: true
----

=== Connection Pool

The Kamelet keeps a pool of connections to the database:

* `maxTotal`: the most connections it opens at the same time, 8 when not set.
* `maxIdle`: the most unused connections it keeps open, 8 when not set.
* `maxWaitMillis`: how long a message waits for a free connection when `maxTotal` are in use, in milliseconds, before
  it fails. When not set, it waits as long as it takes.

[source,yaml,subs='+attributes,macros']
----
maxTotal: 4
maxIdle: 2
maxWaitMillis: 5000
----
